# 烟台消费券 · 定时抢券（Egern 模块）

京东 App 搜「烟台消费券」进专区，券每天限量放。
本模块自动完成两件事：

1. **持续抓包** —— 只要京东 App 在产生流量，就不断用最新的领券请求刷新模板
   （这样模板里的签名参数始终新鲜，隔天重放不容易失效）；
2. **到点重放** —— 每天放券时刻，模块把该请求原样重发，带重试、幂等、结果通知。

> 官方规则（烟台市商务局）：2026-09-25 10:00 首发放放，之后每天 00:00-23:59 限量投放、
> 先到先得；每名消费者每天限领 1 次商品折扣券（15%，最高减 200 元）和 1 次手机专享券；
> **券当日有效，24:00 未使用即失效**。领券需手机定位在烟台、收货地址在烟台、账号实名。

## 先选一条路

| 路线 | 适合谁 | 怎么做 |
|---|---|---|
| **A. 硬件点击**（最干净，推荐） | 想要全自动、又不想装代理 | 看 [TAP.md](TAP.md) |
| **B. 快捷指令**（最省事，10 分钟） | 只想被准时提醒、自己点一下 | 看 [SHORTCUT.md](SHORTCUT.md) |
| **C. Egern 模块** | 想在后台自动重放请求 | 往下看 |
| **D. 组合** | 手动为主，脚本兜底 | 先 B 再 C |

**A 方案**用 CoreDevice RSD 注入真实硬件触控事件，直接点京东 App 里的「领取」——
不用装代理、不用 MITM、不用抓包、不用重放签名，签名和定位由 App 自己处理。
前提是手机开一次「开发者模式」（见 TAP.md）。

> 官方规则是「每日 **00:00-23:59 全天发放**、限量先到先得、领完即止」，
> **不是 0 点整点秒杀**。所以路线 A 在绝大多数情况下完全够用。
> 路线 B 的优势是毫秒级触发 + 全天自动补抢，以及你手速不够时的兜底。

## 安装（3 步，Egern 路线）

### 1. 装 Egern 证书（必须）

Egern → 工具 → 证书 → 生成新证书 → 安装新证书。
不装证书看不到 HTTPS 请求，抓包会失败。

### 2. 添加模块

**一键安装**（点开即可）：

```
egern:/modules/new?name=烟台消费券定时抢券&url=https://raw.githubusercontent.com/VincentCJ/egern-coupon-sniper/main/egern/module-coupon.yaml
```

或手动：Egern → 工具 → 模块 → 右上角 **+** → 填

```
https://raw.githubusercontent.com/VincentCJ/egern-coupon-sniper/main/egern/module-coupon.yaml
```

### 3. 抓一次包（只需做一次）

打开京东 App → 搜索「烟台消费券」→ 进专区 → **手动点一次「领取」**。

模块弹通知「领券模板已刷新」= 成功。之后只要继续用京东 App，模板会自动保持新鲜。

## 之后就不用管了

每天到点（默认 00:00:00）自动重放：

| 情况 | 表现 |
|---|---|
| 抢到 | 推送「✅ 抢到了」，去京东 App「我的-优惠券」看 |
| 已领取 / 达到上限 | 推送「ℹ️ 今日已领取」，当天不再重发 |
| 券已发完 | 推送「😵 券已发完（当天不再重试）」，立即停止 |
| 请求失败 | 推送失败，响应片段保留在脚本状态里 |

**券当天必须用掉**，过期不补。

## 开关：「持续抓取」

持续抓取 = 只要京东 App 有流量就一直抓取并刷新模板。开关有 **两种** 方式：

### 方式一：模块参数（最直接）

Egern → 工具 → 模块 → 点进模块 → 找「持续抓取」→ 改成 `true` / `false` → 保存。

`true` = 打开京东就持续抓取；`false` = 停止抓取，模板保持当前版本。

### 方式二：手动运行开关脚本（即时切换）

Egern → 工具 → 脚本 → 找到 **「烟台消费券-开关」** → 点它运行 → 立刻切换开/关并弹通知。

### 怎么知道开没开

Egern → 分析 → 左上角 → 小组件画廊 → 添加「烟台消费券-状态」到主屏幕，
小组件上会直接显示「持续抓取：开 / 关」。

## 手动试跑（想马上测一次）

Egern → 工具 → 脚本 → 找到 **「烟台消费券-试跑」** → 点它运行。

会立刻按当前模板发一次请求，并把结果弹出来（成功 / 已领 / 抢完 / 失败）。
注意：这算一次真实领券，**券当天有效、领了要当天用掉**。

> 定时脚本（cron 类型）只能按时间自动触发，**点它不会立刻运行**；
> 想手动触发请用上面两个 generic 脚本（试跑 / 开关）。

---

## 反馈说明（为什么有时候没弹通知）

定时抢券脚本每分钟被唤醒一次，所以提示做了节流，避免刷屏：

- 还没到放券时刻 → 每天提示一次「定时抢券已就位，将在 00:00:00 发出」；
- 已经开始发请求 → 每轮都提示结果；
- 当天已处理完 → 每小时最多提示一次「今天已经处理过了」；
- 手动试跑 → **每次都提示**，包括开始和结果。

## 改参数

Egern → 工具 → 模块 → 点进模块 → 改「参数 / Env」：

| 参数 | 说明 | 默认 |
|---|---|---|
| 脚本地址 | coupon-sniper.js 的 raw 地址 | 已默认指向本仓库 |
| 放券时刻 | 每天几点几分几秒发 | `00:00:00` |
| 提前量毫秒 | 提前多少毫秒发（抵消网络延迟） | `50` |
| 重试次数 | 一次最多打多少发 | `40` |
| 重试间隔毫秒 | 两发之间间隔 | `250` |
| 单次超时毫秒 | 单次请求超时 | `6000` |
| 补发模式 | `true` 时若当天放券时刻已过会立刻补打一次 | `false` |
| 持续抓取 | 开关：`true` 持续抓 / `false` 停止 | `true` |
| 抓包匹配 | 自定义哪个 URL 算领券动作（正则，可留空） | 空 |
| 全天补抢 | 仅「排队太挤」等瞬态未果时补抢 | `false` |
| 补抢间隔分钟 | 两次补抢之间隔多少分钟 | `60` |
| 补抢截止 | 补抢到几点为止 | `23:00` |
| 突发发数 | 密集突发阶段打多少发 | `12` |
| 突发间隔毫秒 | 密集突发阶段每发间隔 | `50` |
| 并发发数 | 放券瞬间并发发几发 | `2` |
| 提前量毫秒 | `0`=按实测 RTT 自动；填固定值则强制 | `0` |

## 策略：0 点秒光，所以要「预热 + 密集突发」

实测下来券基本 0 点就抢完，胜负只在放券那一两秒。因此脚本不是「失败了就慢慢重试」，而是：

1. **预热** —— 放券前先打一发到同一 host，DNS/TCP/TLS 就绪，顺带测出真实 RTT；
2. **提前量自适应** —— 按测得的 RTT 提前发送，让请求**到达**服务器时正好是放券瞬间
   （默认 `提前量毫秒=0` 表示自动计算；也可强制固定值）；
3. **密集突发** —— 开头 `突发发数` 发，间隔仅 `突发间隔毫秒`（默认 50ms），
   `并发发数` 决定同一瞬间发几发（默认 2，越高越快也越容易触发风控）；
4. **突发结束才退避** —— 确认是瞬态（排队/网络错）才指数退避；
5. **终态即停** —— 成功 / 已领 / 券发完，立刻收手。

> 「还没到放券时刻」会被判成**瞬态**而不是终态 —— 否则会误以为券没了而提前收手。

## 什么时候停：终态 vs 瞬态

脚本按京东领券接口**真实的返回码语义**决定要不要继续打：

| 返回 | 含义 | 处理 |
|---|---|---|
| `code=0` + `subCode` 命中 `A1\|B1` | 抢到了 | 立即停，当天不再发 |
| 文案含「已领取/重复领取/超过限领」 | 今天已领过这一类 | 立即停 |
| 文案含「已抢完/无库存/名额已满/售罄」 | **券确实发完了** | **立即停，不浪费请求** |
| `code=601` 或文案含「排队/人太多/休息一会」 | 排队太挤，瞬态 | 退避后重试（首轮 <200ms） |
| 网络错误 / 超时 | 瞬态 | 退避后重试 |

所以「券没了还在每 15 分钟重试」这种浪费不会发生：
- 拿到**终态**（成功/已领/发完）→ 当天收工；
- 只有**瞬态**（排队太挤）才值得再来一轮，且默认关闭，需要时在模块里把「全天补抢」打开。

关键词可用 `EMPTY_KEYWORDS` / `CROWDED_KEYWORDS`（逗号分隔）覆盖，以实际返回文案为准。

## 时间精度

- 模块 cron 每分钟触发一次，脚本自己判断是否到点，最后 25ms 用自旋等待；
- 实测触发误差 **5～60 ms**（见 `test/run-tests.js`，81 项自测）；
- 突发阶段实测间隔 45～60ms，突发结束后自动退避（实测 115→166→262→421ms）；
- 提前量默认 50ms，抵消网络 RTT；
- iOS 若把 cron 晚调度 2 分钟内，脚本会立刻补发，不会整晚错过。

---

## 注意事项

- **定位这一关脚本帮不了你**：领券要求手机实时定位在烟台 + 收货地址在烟台，
  脚本只负责精确重放请求，定位由京东按手机位置校验。用虚拟定位属于违反活动规则，
  可能被取消资格。
- **风控**：重试间隔别低于 100ms，别把重试次数调太夸张。
- **MITM 范围**：模块只对 `*.jd.com` 开启 MITM，其他域名不受影响。

### Python 版（备选）

```sh
python3 curl2template.py -f req.txt -o template.json   # 从抓包 cURL 生成模板
python3 grab.py -t template.json --probe --insecure     # 立刻试打一发
python3 grab.py -t template.json --daily 00:00 --days 7 --insecure
```

`--insecure` 用于本机流量走代理中间人的情况。
